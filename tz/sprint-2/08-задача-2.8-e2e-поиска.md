## 🎯 Цель

Сквозной тест полного пути: пользователь вводит вопрос в UI → бэкенд делает retrieval → Claude стримит ответ → UI показывает текст и кликабельные источники. Проверяет, что все слои спринта 2 состыкованы.

## 📋 Контекст для Claude Code

E2E на staging (0.10) с синтетическими данными. Инструмент — Playwright (или Cypress, по стеку фронта Plane). Проверяем реальный стриминг и реальные ссылки, не моки.

## ✅ Что сделать

1. Подготовить сценарий на staging: воркспейс с известными синтетическими задачами (например, задача «починить навбар» с описанием про мобильный релиз).
2. E2E-сценарий:
   - открыть UI поиска
   - ввести вопрос («что известно про мобильный релиз?»)
   - дождаться стриминга ответа (проверить, что текст появляется инкрементально)
   - проверить, что в ответе есть ссылка-источник
   - кликнуть источник → переход на правильную задачу Plane
3. Негативные сценарии:
   - поиск при `ready=false` → ввод заблокирован/предупреждение
   - бюджет исчерпан → понятное сообщение об ошибке

## ✅ Definition of Done

- [ ] E2E проходит: вопрос → стриминг-ответ → источники → переход на задачу
- [ ] Проверена инкрементальность стриминга (текст не появляется разом в конце)
- [ ] Источник кликабелен и ведёт на верную задачу
- [ ] Негативные сценарии (не готов индекс, бюджет) покрыты
- [ ] E2E встроен в CI (на staging, после деплоя)
- [ ] Прогон стабилен (нет флака на таймингах стрима)

## ⚠️ Важно

Стриминг создаёт флак в E2E из-за таймингов — используй явные ожидания появления текста, а не фиксированные sleep. Тест должен быть стабильным, иначе его выключат.
