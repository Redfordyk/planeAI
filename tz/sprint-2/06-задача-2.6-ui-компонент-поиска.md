## 🎯 Цель

Собрать пользовательский интерфейс семантического поиска и встроить его в интерфейс Plane (фронт `apps/web`, Next.js). Поле ввода → стриминг ответа → кликабельные источники.

## 📋 Контекст для Claude Code

Фронт Plane — Next.js (`apps/web`). Используй хуки 2.4 и 2.5. Источники (`source_id`) делать ссылками на соответствующие задачи Plane. Прочитай ONBOARDING.md (0.12) — куда встраивать компонент в layout Plane.

## ✅ Что сделать

1. Компонент `AISearch`:
   - поле ввода запроса + кнопка/Enter
   - индикатор индексации (2.5) — дизейблить ввод, если `ready=false`
   - область ответа: печатается по мере `delta`, поддержка markdown
   - блок источников: ссылки `[work_item:UUID]` → переход на задачу в Plane
   - состояния: loading (стриминг идёт), error (показать `error`), empty
2. Встроить в интерфейс Plane: отдельная панель/модалка/страница (согласовать с Ильёй и ONBOARDING.md).
3. Стилизация в духе Plane (использовать их дизайн-токены/компоненты, не вырвиглазно).
4. Обработать edge-кейсы: пустой запрос, нет прав, бюджет исчерпан (429 → понятное сообщение).

## ✅ Definition of Done

- [ ] Поле поиска + стриминг-ответ работают end-to-end против 2.3
- [ ] Источники кликабельны, ведут на задачи Plane
- [ ] Индикатор индексации блокирует поиск при `ready=false`
- [ ] Ошибки (429/403/провайдер) показываются понятно
- [ ] Markdown в ответе рендерится
- [ ] Компонент встроен в интерфейс Plane, стиль консистентен
- [ ] Адаптивность (десктоп + мобильный)

## ⚠️ Важно

- Источники приходят ПЕРВЫМ кадром (до текста) — покажи их сразу, не жди конца ответа.
- Фронт Plane может обновляться — изолируй компонент, минимизируй вторжение в их код (легче поддерживать при апгрейдах Plane).
