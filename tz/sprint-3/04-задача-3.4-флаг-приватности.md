## 🎯 Цель

UI-переключатель «Исключить проект из ИИ» в настройках проекта + бэкенд-эндпоинт для него. Чтобы команда могла пометить чувствительные проекты, контент которых не должен уходить в OpenAI/Anthropic.

## 📋 Контекст для Claude Code

Модель `AIProjectSettings(project, exclude_from_ai)` создана в 1.1 (отдельная таблица, НЕ поле на Project Plane). Хуки ингеста (1.4) и бэкафилл (1.6) уже проверяют этот флаг. Осталось дать пользователю возможность им управлять. Это и UX-доверие, и предохранитель GDPR.

## ✅ Что сделать

1. Бэкенд: эндпоинты GET/PUT для `AIProjectSettings` проекта (с проверкой, что пользователь — админ проекта; роли из ACL 0.6).
   ```python
   @api_view(["GET","PUT"])
   def project_ai_settings(request, project_id):
       check_project_admin(request.user, project_id)   # только админ проекта
       obj, _ = AIProjectSettings.objects.get_or_create(project_id=project_id)
       if request.method == "PUT":
           obj.exclude_from_ai = request.data["exclude_from_ai"]; obj.save()
           # при включении исключения — удалить уже проиндексированные чанки проекта
           if obj.exclude_from_ai:
               DocumentChunk.objects.filter(project_id=project_id).delete()
       return Response({"exclude_from_ai": obj.exclude_from_ai})
   ```
2. UI: тумблер в настройках проекта Plane с пояснением «контент проекта не будет отправляться в ИИ-сервисы».
3. При включении флага — **удалить уже существующие чанки проекта** (иначе данные остаются в индексе).

## ✅ Definition of Done

- [ ] Эндпоинт GET/PUT настроек ИИ проекта, доступ только админу проекта
- [ ] При включении `exclude_from_ai` существующие чанки проекта удаляются
- [ ] UI-тумблер в настройках проекта с понятным пояснением
- [ ] После включения новый контент проекта не индексируется (проверить с 1.4)
- [ ] Тест: исключённый проект не попадает в индекс и retrieval (связь с 3.5)

## ⚠️ Важно

Удаление уже проиндексированных чанков при включении флага — критично. Иначе пользователь думает «исключил», а данные проекта остаются доступны поиску. Это прямой GDPR-риск.
