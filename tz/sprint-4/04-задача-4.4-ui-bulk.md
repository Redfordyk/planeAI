## 🎯 Цель

Интерфейс bulk-команд: поле ввода команды на естественном языке → показ превью изменений (сколько задач, что меняется, сколько отфильтровано по правам) → кнопка подтверждения → выполнение.

## 📋 Контекст для Claude Code

Бэкенд (4.3) возвращает либо `{type:"answer", text}` (если модель просто ответила), либо `{type:"confirm", confirmed_ids, rejected_count, params, token}`. Выполнение — отдельным запросом с токеном. Это паттерн «опасное действие требует явного подтверждения».

## ✅ Что сделать

1. Поле ввода команды («перенеси все незавершённые задачи из цикла 12 в 13»).
2. Обработка ответа:
   - `type: answer` → показать текст
   - `type: confirm` → показать превью:
     - «Будет обновлено: {confirmed_ids.length} задач»
     - если `rejected_count > 0` → «{rejected_count} задач пропущено (нет прав)»
     - что именно меняется (`params`)
     - кнопки «Подтвердить» / «Отмена»
3. По «Подтвердить» → запрос выполнения с `token` → показать результат «Обновлено N задач».
4. Состояния loading/error, обработка 429/403/недействительный токен.

## ✅ Definition of Done

- [ ] Поле команды работает, ответ-текст показывается
- [ ] Превью изменений с числом задач и `rejected_count`
- [ ] Подтверждение выполняет действие через токен
- [ ] Результат выполнения показывается
- [ ] Отмена не выполняет ничего
- [ ] Ошибки (нет прав, бюджет, битый токен) понятны
- [ ] Стиль консистентен с Plane

## ⚠️ Важно

Превью ОБЯЗАТЕЛЬНО до выполнения — пользователь должен видеть, что именно изменится и сколько задач отфильтровано по правам. Никаких «молча выполнить bulk». Это и UX, и безопасность.
