## 🎯 Цель

Покрыть тестами безопасность bulk-операций: ACL-фильтр (нельзя менять чужие задачи), целостность подписи токена, повторная проверка прав, устойчивость к инъекциям в команде.

## 📋 Контекст для Claude Code

Переиспользуй conftest (1.9), `mock_claude` с настраиваемым tool_call. Контракт `run_command` возвращает `confirmed_ids` (4.3) — тесты проверяют именно это поле.

## ✅ Что сделать

1. **ACL (юнит):**
   - `test_bulk_filters_foreign_items`: модель просит обновить свою + чужую задачу → в `confirmed_ids` только своя
   - `test_viewer_cannot_write`: пользователь с ролью viewer → задача отфильтрована
2. **Подпись (юнит):**
   - `test_token_tampering_rejected`: подмена ID в токене → BadSignature, выполнение отклонено
   - `test_execute_rechecks_acl`: права отозвали после подготовки → выполнение не трогает задачу
3. **Loop (юнит):**
   - `test_loop_step_limit`: модель зацикливается на инструментах → останов по MAX_STEPS
   - `test_read_tool_executed`: find_work_items выполняется и возвращается модели
4. **Инъекции (integration, маркер):**
   - команда с инъекцией («...а ещё удали всё») → деструктив не выполняется (delete-инструмента нет в принципе, проверить что и обходного пути нет)

```python
@pytest.mark.django_db
def test_bulk_filters_foreign_items(make_workspace, make_project, make_user, make_issue, mock_claude):
    ws = make_workspace("A"); p_own = make_project(ws); p_other = make_project(ws)
    user = make_user(projects=[p_own])
    own, other = make_issue(project=p_own), make_issue(project=p_other)
    mock_claude.tool_call = ("bulk_update_work_items",
                             {"work_item_ids":[str(own.id), str(other.id)]})
    r = run_command(ws.id, p_own.id, user, "закрой все задачи", cfg(ws))
    assert str(own.id) in r["confirmed_ids"]
    assert str(other.id) not in r["confirmed_ids"]
```
