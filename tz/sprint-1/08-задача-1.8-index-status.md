## 🎯 Цель

API-эндпоинт, показывающий, насколько проиндексирован воркспейс. Нужен, чтобы фронт не давал пользоваться поиском на пустом/неполном индексе и показывал прогресс бэкафилла («340/512, 66%»).

## 📋 Контекст для Claude Code

После включения ИИ или старта бэкафилла индекс наполняется не мгновенно. Если пользователь ищет по пустому индексу — Claude скажет «данных нет», и впечатление будет «ИИ тупой». Эндпоинт даёт честный статус готовности.

## ✅ Что сделать

```python
# ai/views.py
from rest_framework.decorators import api_view
from rest_framework.response import Response

@api_view(["GET"])
def index_status(request, workspace_id):
    total = Issue.objects.filter(workspace_id=workspace_id).count()
    indexed = (DocumentChunk.objects
        .filter(workspace_id=workspace_id, source_type="work_item")
        .values("source_id").distinct().count())
    coverage = round(indexed / total, 2) if total else 1.0
    return Response({
        "total_work_items": total,
        "indexed": indexed,
        "coverage": coverage,
        "ready": indexed >= total * 0.95,
    })
```

Доп:
- Проверка прав: пользователь видит статус только своего воркспейса.
- Зарегистрировать URL (с учётом ONBOARDING.md — куда Plane монтирует роуты).
- Опционально: разбивка по source_type (work_item/comment/page).

## 🔍 Проверка

```bash
curl http://localhost/api/ai/<workspace_id>/index-status/
# {"total_work_items":512,"indexed":340,"coverage":0.66,"ready":false}
```

## ✅ Definition of Done

- [ ] Эндпоинт возвращает total / indexed / coverage / ready
- [ ] URL зарегистрирован и доступен
- [ ] Проверка прав на воркспейс
- [ ] Корректно при пустом воркспейсе (coverage=1.0, ready=true)
- [ ] Тест на расчёт покрытия

## ⚠️ Важно

`ready` при 95% покрытия — порог, чтобы единичные неиндексируемые объекты (пустые/приватные) не блокировали готовность вечно.
