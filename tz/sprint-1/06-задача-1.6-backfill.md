## 🎯 Цель

Команда, проиндексирующая ВСЕ существующие задачи/комментарии/страницы воркспейса — для первичного наполнения индекса. С дросселированием, чтобы не залить очередь и не словить 429 от OpenAI разом.

## 📋 Контекст для Claude Code

При включении ИИ в существующем воркспейсе данные уже есть, но не проиндексированы. Нужен разовый прогон, ставящий `reindex_source` (из 1.5) для каждого объекта. На тысячах задач без throttle очередь забьётся и провайдер вернёт rate-limit.

## ✅ Что сделать

```python
# ai/management/commands/backfill_embeddings.py
from django.core.management.base import BaseCommand
from <app>.models import Issue, IssueComment, Page   # SCHEMA.md

class Command(BaseCommand):
    def add_arguments(self, parser):
        parser.add_argument("--workspace", required=True)
        parser.add_argument("--rate", type=int, default=3)  # задач/сек постановки

    def handle(self, *args, **o):
        ws = o["workspace"]; rate = o["rate"]; n = 0
        for issue in Issue.objects.filter(workspace_id=ws).iterator(chunk_size=200):
            if _excluded(issue.project_id):
                continue
            reindex_source.apply_async(
                args=[str(ws), str(issue.project_id), "work_item", str(issue.id)],
                countdown=n // rate)
            n += 1
        # аналогично IssueComment, Page
        self.stdout.write(f"Enqueued {n} reindex tasks for workspace {ws}")
```

Доп:
- Флаг `--dry-run` (только посчитать, не ставить).
- Пропуск приватных проектов (`exclude_from_ai`).
- Лог прогресса.

## 🔍 Запуск

```bash
docker compose exec api python manage.py backfill_embeddings --workspace <uuid> --rate 3
# следить за прогрессом — через index-status (1.8)
```
