## 🎯 Цель

Создать миграции для приложения `ai`, включая активацию расширения `vector` в Postgres и HNSW-индекс на поле эмбеддинга. Без расширения миграция модели упадёт.

## 📋 Контекст для Claude Code

`DocumentChunk.embedding` — это `VectorField(1536)` с HNSW-индексом. Django-миграция не активирует расширение сама — нужен отдельный `RunSQL` с `CREATE EXTENSION` ПЕРЕД созданием таблицы. Версия pgvector должна быть ≥0.8.2 (см. PGVECTOR.md, задача 0.4) из-за CVE-2026-3172 при HNSW-сборке.

## ✅ Что сделать

1. Создать data-миграцию, первой операцией активирующую расширение:
   ```python
   # ai/migrations/0001_enable_pgvector.py
   from django.db import migrations
   class Migration(migrations.Migration):
       dependencies = []
       operations = [
           migrations.RunSQL(
               sql="CREATE EXTENSION IF NOT EXISTS vector;",
               reverse_sql="DROP EXTENSION IF EXISTS vector;",
           ),
       ]
   ```
2. Сгенерировать миграции моделей: `makemigrations ai` (зависят от 0001).
3. Применить через штатный механизм Plane (`migrator`) или напрямую:
   ```bash
   docker compose exec api python manage.py makemigrations ai
   docker compose run --rm migrator   # или migrate ai
   ```
4. Проверить, что HNSW-индекс реально создан и расширение активно.
5. Если pgvector <0.8.2 и апгрейд отложен — добавить в миграцию workaround из PGVECTOR.md (`SET max_parallel_maintenance_workers=0` на время сборки).

## 🔍 Команды проверки

```bash
docker compose exec plane-db psql -U plane -d plane -c "SELECT extname, extversion FROM pg_extension WHERE extname='vector';"
docker compose exec plane-db psql -U plane -d plane -c "\d ai_documentchunk"      # таблица есть
docker compose exec plane-db psql -U plane -d plane -c "\di chunk_hnsw_idx"        # индекс есть
```
