## 🎯 Цель

Финальный приёмочный прогон на проде: проиндексировать реальные данные команды (бэкафилл) и проверить весь функционал на боевом окружении перед открытием доступа команде.

## 📋 Контекст для Claude Code

Это первый запуск на РЕАЛЬНЫХ данных команды — значит DPA (0.7) должен быть закрыт, приватные проекты помечены (3.4). Бэкафилл реальных задач уходит в облако, поэтому порядок: сначала GDPR-готовность, потом индексация.

## ✅ Что сделать

1. **Предусловия (проверить!):** DPA закрыт (0.7), приватные проекты помечены (3.4), бэкап сделан (6.1).
2. Запустить боевой бэкафилл (1.6) с дросселированием, следить за прогрессом через index-status (1.8) и дашборд токенов (6.3).
3. Дождаться готовности индекса (`ready=true`).
4. Приёмочный чек на проде (smoke всех фич):
   - поиск возвращает осмысленные ответы по реальным задачам
   - саммари/генерация работают
   - bulk через подтверждение
   - агенты (если go получен в 5.8) — на ограниченном наборе сначала
   - дашборд показывает реальный расход
   - алерты настроены и срабатывают
5. Зафиксировать стоимость бэкафилла (сколько реально стоила индексация).

## ✅ Definition of Done

- [ ] Предусловия GDPR проверены ДО бэкафилла
- [ ] Боевой бэкафилл завершён, `ready=true`
- [ ] Все фичи проверены на проде (smoke)
- [ ] Дашборд и алерты работают на боевых данных
- [ ] Стоимость бэкафилла зафиксирована
- [ ] Приватные проекты подтверждённо НЕ проиндексированы
- [ ] Отчёт о готовности к релизу

## ⚠️ Важно

НЕ запускать бэкафилл реальных данных, пока не закрыт DPA (0.7) и не помечены приватные проекты (3.4). Иначе данные команды уйдут в облако без правового основания и без учёта приватности. Порядок строгий: GDPR → бэкап → бэкафилл.
