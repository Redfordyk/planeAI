## 🎯 Цель

Финальная проверка соответствия GDPR перед открытием доступа команде. Команда в EU (Франкфурт), данные уходят в OpenAI/Anthropic — нужно подтвердить правовую и техническую готовность.

## 📋 Контекст (организационная задача)

Свести воедино всё, что касается обработки персональных данных: DPA, правовое основание, механизмы приватности, прозрачность для пользователей. Это gate: без зелёного чеклиста — не релизить на реальных данных.

## ✅ Что сделать

Пройти чеклист и зафиксировать в `GDPR-RELEASE.md`:
1. **DPA:** подписаны с OpenAI и Anthropic (0.7), подтверждения в наличии.
2. **Zero-retention / отказ от обучения:** включены где доступно.
3. **Правовое основание:** определено (легитимный интерес / согласие команды).
4. **Приватные проекты:** механизм исключения работает (3.4), чувствительные проекты помечены, их чанки удалены из индекса.
5. **Прозрачность:** команда уведомлена, что контент задач обрабатывается ИИ-провайдерами; есть документ для сотрудников.
6. **Минимизация:** уходит только необходимый контент (текст задач), не лишние персональные данные.
7. **Право на удаление:** при удалении задачи её чанки удаляются (проверить delete_chunks из 1.5).
8. **Реестр обработки:** обновлён (какие данные, куда, зачем, как долго).

## ✅ Definition of Done

- [ ] Все 8 пунктов чеклиста пройдены и задокументированы
- [ ] DPA подтверждены, zero-retention включён
- [ ] Приватные проекты исключены и проверены
- [ ] Команда уведомлена об обработке данных
- [ ] Удаление задачи чистит её эмбеддинги (проверено)
- [ ] `GDPR-RELEASE.md` подписан ответственным
- [ ] Решение: можно ли релизить на реальных данных (go/no-go)

## ⚠️ Важно

Это юридический gate, не технический. Даже если код идеален — без закрытого DPA и правового основания обработка персональных данных команды в облаке незаконна. No-go здесь означает: либо доработать соответствие, либо релизить только на неперсональных/синтетических данных.
