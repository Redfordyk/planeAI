## 🎯 Цель

Подготовить и протестировать процедуру отката: если релиз сломал прод — быстро вернуться к рабочему состоянию (предыдущий образ + при необходимости откат миграций/данных).

## 📋 Контекст для Claude Code

Образы тегируются по SHA (0.9), бэкап есть (6.1). Откат = вернуть предыдущий образ + откатить миграции, если они были деструктивными. Особый случай: ИИ-надстройку можно «выключить» (флаг `enabled` в WorkspaceAIConfig), не трогая сам Plane — это самый быстрый откат для проблем именно ИИ-слоя.

## ✅ Что сделать

1. **Быстрый откат ИИ-слоя:** `enabled=False` в конфиге → ИИ-эндпоинты отдают 403, Plane работает как обычный трекер. Это первый шаг при любой проблеме ИИ.
2. **Откат образа:** вернуть предыдущий тег `plane-backend-ai` (по SHA), `docker compose up -d`.
3. **Откат миграций:** если релиз содержал миграции `ai` — `migrate ai <предыдущий_номер>`. Проверить обратимость заранее.
4. **Откат данных:** только если повреждены — restore из бэкапа (6.1).
5. Протестировать на staging полный цикл: сломать → откатить → убедиться что работает.
6. Документировать в `ROLLBACK.md`: дерево решений «что сломалось → какой уровень отката».

## ✅ Definition of Done

- [ ] Быстрое выключение ИИ-слоя через флаг работает (Plane остаётся жив)
- [ ] Откат образа на предыдущий SHA отработан
- [ ] Откат миграций `ai` обратим и протестирован
- [ ] Процедура restore данных задокументирована (ссылка на 6.1)
- [ ] Полный цикл откат протестирован на staging
- [ ] `ROLLBACK.md` с деревом решений

## ⚠️ Важно

Ключевое преимущество архитектуры: ИИ-слой отделён от Plane. При проблеме именно с ИИ — выключаешь флаг, и Plane работает как ни в чём не бывало. Это самый безопасный откат, начинай всегда с него, прежде чем катить образы назад.
