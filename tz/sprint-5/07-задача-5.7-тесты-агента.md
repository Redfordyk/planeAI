## 🎯 Цель

Покрыть тестами безопасность автономного агента — самую рискованную часть проекта. Проверить: ограничение белым списком, scope проекта, отсутствие деструктива, защиту от петли, полноту аудита.

## 📋 Контекст для Claude Code

Переиспользуй conftest (1.9). Агент действует автономно, поэтому тесты — это последний барьер перед тем, как дать ему писать данные. Особый фокус: что бы модель ни «попросила», код не позволит выйти за границы.

## ✅ Что сделать

1. **Ограничение инструментов:**
   - `test_agent_cannot_delete`: модель пытается вызвать delete → инструмента нет, действие не выполняется
   - `test_agent_whitelist_only`: вызов инструмента вне `AGENT_TOOLS` → отклонён
2. **Scope проекта:**
   - `test_agent_stays_in_project`: модель пытается изменить задачу другого проекта → отклонено
   - `test_agent_no_cross_workspace`: попытка тронуть чужой воркспейс → отклонено
3. **Защита от петли:**
   - `test_agent_no_self_trigger`: изменение, сделанное агентом, не запускает агента повторно
   - `test_agent_action_limit`: лимит действий за запуск соблюдается
4. **Аудит:**
   - `test_every_action_logged`: каждое действие агента попадает в аудит-лог
5. **Сценарии (юнит на логику, мок Claude):**
   - триаж проставляет приоритет/метки, не назначает жёстко
   - дедуп предлагает, не закрывает
   - авто-описание не затирает существующее

## ✅ Definition of Done

- [ ] Тест отсутствия delete — зелёный
- [ ] Тест белого списка инструментов — зелёный
- [ ] Тест scope проекта — зелёный
- [ ] Тест отсутствия кросс-воркспейс — зелёный
- [ ] Тест защиты от петли самозапуска — зелёный
- [ ] Тест лимита действий — зелёный
- [ ] Тест полноты аудита — зелёный
- [ ] Тесты сценариев (триаж/дедуп/описание) — зелёные
- [ ] Все в блокирующем наборе PR

## ⚠️ Важно (критично)

Это последний барьер перед автономной записью. Тесты scope, белого списка и петли — НЕ опциональны. Если хоть один не зелёный — агента на staging не выкатывать (gate 5.8). Петля самозапуска отдельно опасна: способна за минуты сжечь весь бюджет.
