## 🎯 Цель

Ядро агента: Celery-задача, которая читает задачу + RAG-контекст, решает действие через agent loop (4.2), и выполняет ОГРАНИЧЕННЫЙ набор write-операций в пределах одного проекта. Это автономная запись — поэтому самые жёсткие ограничения.

## 📋 Контекст для Claude Code

Связка фаз 2 (retrieve) + 4 (agent loop). Но в отличие от bulk (где человек подтверждает), агент действует автономно — значит ограничения должны быть в КОДЕ. Принципы: scope ОДНОГО проекта, белый список безопасных действий, никаких удалений, никаких изменений прав/шеринга, всё в аудит-лог.

## ✅ Что сделать

```python
# ai/agent_worker.py
from celery import shared_task

# БЕЛЫЙ список действий агента (только безопасные)
AGENT_TOOLS = ["find_work_items", "set_labels", "set_priority",
               "suggest_assignee", "update_description"]
# Явно ЗАПРЕЩЕНО: delete, изменение прав, шеринг, изменение вне своего проекта

@shared_task(bind=True, max_retries=2)
def run_agent_on_workitem(self, issue_id):
    issue = Issue.objects.get(id=issue_id)
    agent = get_agent_for_workspace(issue.workspace_id)
    if not agent.enabled:
        return

    # 1. контекст: сама задача + похожие через RAG (только её проект!)
    context = retrieve(issue.workspace_id, agent.user, issue_text(issue), cfg(issue))

    # 2. agent loop с УРЕЗАННЫМ набором инструментов
    result = run_command(issue.workspace_id, issue.project_id, agent.user,
                         build_agent_prompt(issue, context), cfg(issue),
                         allowed_tools=AGENT_TOOLS)   # ограничение!

    # 3. выполнение — ТОЛЬКО в пределах issue.project_id, ТОЛЬКО из белого списка
    apply_agent_actions(result, project_id=issue.project_id, agent=agent)

    # 4. аудит (обязательно)
    log_agent_action(agent, issue, result)
```

Жёсткие требования:
- `allowed_tools` ограничивает инструменты белым списком — модель физически не может вызвать запрещённое.
- Любое действие проверяется: целевая задача в `issue.project_id`? иначе отклонить.
- Никаких delete, изменения прав, шеринга, кросс-проектных операций.
- Каждое действие → аудит-лог (5.7 проверяет).
- Лимит действий за один запуск (защита бюджета).

## ✅ Definition of Done

- [ ] Воркер читает задачу + RAG-контекст её проекта
- [ ] Agent loop работает с УРЕЗАННЫМ `allowed_tools`
- [ ] Действия выполняются ТОЛЬКО в пределах проекта задачи
- [ ] Запрещённые действия (delete/права/кросс-проект) невозможны
- [ ] Каждое действие пишется в аудит-лог
- [ ] Лимит действий за запуск
- [ ] Тесты (5.7): ограничение прав, scope проекта, аудит

## ⚠️ Важно (критично)

Это автономная запись без человека. Три предохранителя обязательны:
1. **Белый список инструментов** — не «запретить плохое», а «разрешить только хорошее».
2. **Scope проекта** — агент не выходит за пределы своего проекта, даже если модель попросит.
3. **Аудит всего** — каждое действие логируется, иначе нельзя расследовать инцидент.
