## 🎯 Цель

Создать «виртуального пользователя» — ИИ-агента в воркспейсе с ограниченными правами, и триггер: при назначении задачи на агента (или метке `ai-agent`) запускается фоновая обработка.

## 📋 Контекст для Claude Code

Агент — это пользователь Plane с урезанными правами (scope одного проекта, без админских прав, без удаления). Триггер — сигнал на изменение задачи. Запуск обработки — Celery-задача (асинхронно, не блокирует), как в 1.4. Имена моделей — из SCHEMA.md.

## ✅ Что сделать

1. Создать агента как пользователя с пометкой `is_ai_agent` (отдельная таблица `AIAgent`, не поле на User Plane):
   ```python
   # ai/models.py (дополнение)
   class AIAgent(models.Model):
       user      = models.OneToOneField("<app>.User", on_delete=models.CASCADE)
       workspace = models.ForeignKey("<app>.Workspace", on_delete=models.CASCADE)
       enabled   = models.BooleanField(default=True)
   ```
2. Триггер через сигнал (по аналогии с 1.4, `transaction.on_commit`):
   ```python
   @receiver(post_save, sender=Issue)
   def trigger_agent(sender, instance, **kwargs):
       if not _ai_enabled(instance.workspace_id):
           return
       if is_assigned_to_agent(instance) or has_label(instance, "ai-agent"):
           transaction.on_commit(
               lambda: run_agent_on_workitem.delay(str(instance.id)))
   ```
3. Защита от повторного запуска (дебаунс/флаг «уже в обработке»), чтобы изменения, сделанные самим агентом, не триггерили его повторно (петля!).

## ✅ Definition of Done

- [ ] Модель `AIAgent` (отдельная таблица, не поле на User)
- [ ] Агент создаётся с ограниченными правами (scope проекта, не админ)
- [ ] Триггер по назначению/метке через `transaction.on_commit`
- [ ] Защита от петли: действия агента не триггерят его повторно
- [ ] Тест: назначение на агента ставит ровно одну задачу обработки

## ⚠️ Важно (критично)

**Петля самозапуска** — главный риск. Агент меняет задачу → срабатывает `post_save` → агент запускается снова → бесконечный цикл, жгущий бюджет. Обязательна защита: флаг «изменено агентом» / дебаунс / проверка инициатора изменения. Без неё агента НЕ включать.
