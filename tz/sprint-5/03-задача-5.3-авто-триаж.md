## 🎯 Цель

Сценарий агента: новая входящая задача автоматически классифицируется — проставляется приоритет, метки, предлагается исполнитель. Без удаления и без необратимых действий.

## 📋 Контекст для Claude Code

Один из трёх автономных сценариев (5.3–5.5), все поверх воркера 5.2. Триаж = классификация + проставление безопасных полей. Предложение исполнителя — именно предложение (метка/коммент), не жёсткое назначение, чтобы не было ошибочных эскалаций.

## ✅ Что сделать

1. Промпт триажа: на вход — текст задачи + контекст проекта (метки, типичные приоритеты), на выход — структурированное решение (приоритет, метки, кандидат-исполнитель).
2. Действия (из белого списка 5.2):
   - `set_priority` — проставить приоритет
   - `set_labels` — навесить релевантные метки (из существующих в проекте, не создавать новые без надобности)
   - `suggest_assignee` — предложить исполнителя (комментарием или меткой, не жёстким назначением)
3. Идемпотентность: повторный триаж уже обработанной задачи не дублирует действия.
4. Аудит каждого действия.

## ✅ Definition of Done

- [ ] Новая задача автоматически получает приоритет и метки
- [ ] Исполнитель предлагается (не назначается жёстко)
- [ ] Используются только существующие метки проекта (или создание контролируется)
- [ ] Идемпотентность (повторный триаж не дублирует)
- [ ] Все действия в аудит-логе
- [ ] Тест на синтетических задачах staging

## ⚠️ Важно

«Предложить исполнителя» ≠ «назначить». Ошибочное автоназначение раздражает и ломает доверие. Агент предлагает, человек решает. Жёсткое назначение — только если команда явно этого захочет (отдельная настройка).
