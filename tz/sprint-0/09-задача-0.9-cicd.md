## 🎯 Цель

Настроить CI/CD: на каждый PR — линт + тесты, на merge в основную ветку — сборка backend-образа `plane-backend-ai` и автодеплой на staging. Чтобы 5 человек не катили руками.

## 📋 Контекст для Claude Code

Используем GitHub Actions (или GitLab CI — уточнить, где репозиторий). Образ собирается из `Dockerfile.ai` (задача 0.5). Тесты — pytest + pytest-django + pytest-asyncio. Фронт — отдельный шаг (lint + build React-компонентов).

## ✅ Что сделать

1. Pipeline `ci.yml`:
   - **lint**: ruff/flake8 (Python), eslint (JS)
   - **test**: pytest с поднятым Postgres+pgvector (service container), прогон юнит-тестов приложения `ai`
   - **build**: `docker build -f Dockerfile.ai`, тег по commit SHA + ветке
   - **push**: в реестр (GitHub Container Registry / приватный)
2. Pipeline `deploy-staging.yml`: на merge в `main` — pull образа на staging-сервер, `docker compose up -d` с новым образом, прогон миграций (`migrator`), smoke-тест (curl health-эндпоинта).
3. Секреты CI (ключи реестра, SSH на staging) — через секреты CI, НЕ в коде.
4. Бейдж статуса сборки в README.

## 📦 Артефакты

- `.github/workflows/ci.yml` (или `.gitlab-ci.yml`)
- `.github/workflows/deploy-staging.yml`
- Настроенный реестр образов
- `CICD.md`: как работает пайплайн, как откатиться

## ✅ Definition of Done

- [ ] PR запускает lint + test, красный PR не мержится
- [ ] Тесты гоняются с реальным Postgres+pgvector в CI
- [ ] Merge в main собирает и пушит образ с тегом по SHA
- [ ] Автодеплой на staging работает, smoke-тест проходит
- [ ] Секреты в CI-секретах, не в репозитории
- [ ] CICD.md закоммичен

## ⚠️ Важно

- Тесты в CI должны поднимать pgvector ≥0.8.2 (см. 0.4) — иначе HNSW-миграция в тестах упадёт.
- Тегируй образы по SHA, не только `latest` — это основа отката (6.5).
- Staging должен существовать (0.10) до включения автодеплоя — учти порядок.
