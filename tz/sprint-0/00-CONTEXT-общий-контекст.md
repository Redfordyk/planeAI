# 📌 Общий контекст проекта (читать перед любым ТЗ)

> Этот файл — общий контекст для всех задач. Прикладывай его к промпту Claude Code вместе с конкретным ТЗ задачи, либо держи в `CLAUDE.md` репозитория.

## Что строим

ИИ-надстройка над self-hosted **Plane** (open-source аналог Jira/Linear, Community Edition, AGPLv3). Надстройка добавляет:
- семантический поиск по задачам (RAG + Claude),
- авто-саммари и генерацию,
- bulk-операции на естественном языке,
- ИИ-агентов для триажа.

Plane мы **не форкаем целиком** — добавляем отдельное Django-приложение `ai` и пересобираем backend-образ поверх официального.

## Архитектура (зафиксировано)

| Слой | Решение |
|---|---|
| Трекер | Plane CE, self-hosted, Docker Compose |
| Backend | Django + DRF (в репозитории Plane: `apps/api`) |
| Очереди | Celery + RabbitMQ + Redis (уже в стеке Plane) |
| БД | PostgreSQL (уже в стеке Plane) |
| Вектора | **pgvector** в той же Postgres (НЕ отдельный сервис) |
| Чат-модель | **Claude** (Anthropic API), `claude-sonnet-4-6` дефолт, `claude-haiku-4-5-20251001` для дешёвых операций |
| Эмбеддинги | **OpenAI** `text-embedding-3-small` (1536 dim) — Claude эмбеддинги не отдаёт |
| Объектное хранилище | S3-совместимое (MinIO в стеке Plane) — для AI-артефактов |

## Ключевые принципы (НЕ нарушать)

1. **Изоляция воркспейсов.** Любой retrieval / любая запись фильтруется по `workspace_id` + правам пользователя. Утечка между воркспейсами = критический баг (Plane уже патчил IDOR через границы воркспейсов).
2. **ACL в коде, не «по слову модели».** LLM выбирает действие, но выполняет его наш код после проверки прав.
3. **Контент задач = недоверенный ввод.** Защита от prompt-injection: пользовательский текст идёт в `user`-сообщение, инструкции — только в `system`.
4. **Бюджет токенов.** Каждый LLM-вызов учитывается; при превышении месячного лимита воркспейса — 429.
5. **GDPR.** Текст уходит в OpenAI/Anthropic → нужен DPA + zero-retention. Приватные проекты исключаются из индексации флагом.
6. **Не вторгаться в схему Plane.** Свои данные — в своих таблицах приложения `ai`, без новых полей на чужих моделях.

## ⚠️ Неверифицированные допущения (проверяются в задаче 0.2)

Имена моделей Plane предполагаются и ДОЛЖНЫ быть подтверждены скриптом верификации (задача 0.2) до написания кода спринта 1:

**До подтверждения 0.2 — не хардкодить эти имена в коде.**

## Модели данных приложения `ai` (целевые)

- `DocumentChunk` — чанки контента + эмбеддинг (vector 1536) + workspace/project + source_type/source_id + content_hash
- `WorkspaceAIConfig` — ключи (шифрованы), модели, бюджет токенов, enabled
- `AIUsageLog` — учёт каждого LLM-вызова (фича, модель, токены, $)
- `AIProjectSettings` — `exclude_from_ai` на проект (вместо поля на чужой модели)

## Формат работы с Claude Code

Каждое ТЗ написано как промпт: контекст → задача → требования → проверка → критерии готовности (DoD). Исполнитель прикладывает этот файл + общий контекст к Claude Code и итеративно доводит до прохождения DoD.
