## 🎯 Цель

Юридически и технически подготовить отправку данных в облачные ИИ-провайдеры. Контент задач уходит в **OpenAI** (эмбеддинги) и **Anthropic** (генерация) — для команды в EU (Франкфурт) это трансфер данных по GDPR, требующий DPA, SCC и правового основания.

## 📋 Контекст (не код — организационная задача)

RAG-ловушка: отправка контента пользователей в OpenAI для эмбеддинга = GDPR data transfer. Нужны: DPA (Data Processing Agreement) с каждым провайдером, Standard Contractual Clauses, и по возможности zero-retention (провайдер не хранит и не обучается на данных).

## ✅ Что сделать

1. **OpenAI:** в настройках организации API оформить DPA, включить zero-retention / отказ от обучения на данных. Сохранить подтверждение.
2. **Anthropic:** аналогично — DPA + подтверждение, что данные не используются для обучения (по умолчанию API-данные Anthropic не используются для обучения, но зафиксировать письменно).
3. Завести **отдельные API-ключи под этот проект** (не личные), с лимитами расходов на стороне провайдера.
4. Описать в `GDPR.md`: какие данные уходят, куда, на каком правовом основании, статус DPA по каждому провайдеру, ссылки на подтверждения.
5. Согласовать с командой политику: какие проекты НЕ должны индексироваться (готовит почву для флага `exclude_from_ai`, задача 3.4).

## 📦 Артефакты

- `GDPR.md`: реестр трансферов, статус DPA, правовое основание
- Подтверждения DPA от обоих провайдеров (приложить/сослаться)
- Отдельные проектные API-ключи (передать Косте для задачи 0.11 — хранение секретов)
