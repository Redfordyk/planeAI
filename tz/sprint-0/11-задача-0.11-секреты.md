## 🎯 Цель

Настроить безопасное хранение секретов: API-ключи Anthropic/OpenAI, ключ шифрования полей БД, секреты Plane. Никаких ключей в git, в логах, в URL.

## 📋 Контекст для Claude Code

Ключи Claude/OpenAI хранятся в БД (`WorkspaceAIConfig`) **в зашифрованном виде** (`django-encrypted-model-fields` или аналог) — значит нужен мастер-ключ шифрования, который сам где-то лежит безопасно. Плюс ключи провайдеров для бэкафилла/настройки. Принцип из общего контекста: секреты — в окружении/Vault, не в коде; не логировать; не класть в URL.

## ✅ Что сделать

1. Выбрать механизм: для прототипа — `.env` вне git + права 600 + Docker secrets; цель — Vault/SOPS если дойдёт до серьёзного прода. Зафиксировать в `SECRETS.md`.
2. Сгенерировать и безопасно хранить `FIELD_ENCRYPTION_KEY` (для шифрования ключей в БД).
3. Завести `.env.example` (без значений) + реальный `.env` в `.gitignore`.
4. Проверить, что ключи НЕ попадают: в git (`git log -p | grep -i key`), в логи приложения, в сообщения об ошибках, в URL-параметры.
5. Описать процедуру ротации: как заменить скомпрометированный ключ Anthropic/OpenAI без даунтайма.

## 🔍 Проверка

```bash
git ls-files | xargs grep -lE "sk-ant-|sk-proj-" 2>/dev/null   # должно быть ПУСТО
grep -rE "sk-ant-|sk-" logs/ 2>/dev/null                        # ключей в логах нет
```

## 📦 Артефакты

- `.env.example` (шаблон без значений)
- `.gitignore` с `.env`
- `SECRETS.md`: где что хранится, как ротировать
- Сгенерированный `FIELD_ENCRYPTION_KEY` (в защищённом хранилище, НЕ в репо)

## ✅ Definition of Done

- [ ] Ни одного секрета в git-истории (проверено grep'ом)
- [ ] `FIELD_ENCRYPTION_KEY` сгенерирован и хранится безопасно
- [ ] `.env` в `.gitignore`, есть `.env.example`
- [ ] Ключи не попадают в логи и ошибки (проверено)
- [ ] Процедура ротации задокументирована
- [ ] SECRETS.md закоммичен

## ⚠️ Важно

Из правил безопасности проекта: если ключ когда-либо засветился в git-истории — он скомпрометирован, ротировать обязательно (история git вечна). Лучше сразу не допускать.
