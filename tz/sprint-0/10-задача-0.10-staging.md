## 🎯 Цель

Поднять отдельный staging-контур — копию прод-конфигурации Plane + ИИ-надстройка. Здесь тестируются опасные вещи (bulk-операции, агенты с автономной записью) до выката на прод.

## 📋 Контекст для Claude Code

Bulk-операции и агенты МОГУТ менять/массово трогать задачи. Тестировать это на проде с реальными данными команды нельзя. Нужен изолированный контур с тестовыми данными, идентичный проду по конфигу.

## ✅ Что сделать

1. Поднять второй экземпляр Plane (отдельный сервер/VM или namespace) с тем же `docker-compose` + `docker-compose.override.yml` (образ `plane-backend-ai`).
2. Заполнить тестовыми/синтетическими данными (НЕ боевыми данными команды — GDPR).
3. Завести отдельные ИИ-ключи (или те же с лимитом) и отдельный бюджет токенов.
4. Подключить как цель автодеплоя из CI (0.9).
5. Изолировать сеть: staging не должен ходить в прод-БД.

## 📦 Артефакты

- Работающий staging-Plane с ИИ-надстройкой
- Синтетический датасет задач для тестов
- `STAGING.md`: адрес, доступы, чем отличается от прода, как накатывать

## ✅ Definition of Done

- [ ] Staging поднят, доступен команде
- [ ] Конфигурация идентична проду (тот же образ, те же переменные кроме секретов/данных)
- [ ] Заполнен синтетическими данными
- [ ] CI автодеплоит сюда (связка с 0.9 работает)
- [ ] Изоляция от прод-данных подтверждена
- [ ] STAGING.md закоммичен

## ⚠️ Важно

На staging НИКОГДА не заливать реальные данные команды — это контур для разрушительных тестов. Только синтетика.
