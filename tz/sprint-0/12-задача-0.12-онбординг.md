## 🎯 Цель

Подготовить краткий навигатор по кодовой базе Plane backend для команды: где модели, где DRF-вьюхи, где Celery-задачи, где сигналы, как добавляется новое приложение, как локально гонять тесты. Чтобы Костя/Вова/Никита не тратили время на разведку поодиночке.

## 📋 Контекст для Claude Code

Backend Plane — Django (`apps/api`), стек Python + DRF + Postgres + Redis + Celery + RabbitMQ. Команда хорошо владеет Django и Claude Code, нужен не учебник, а карта: где что лежит именно в Plane и куда мы подключаем `ai`.

## ✅ Что сделать

1. Составить `ONBOARDING.md` — карту репозитория backend:
   - где Django settings, как подключаются приложения,
   - где модели (привязать к SCHEMA.md из 0.2),
   - где DRF-вьюхи и роутинг URL,
   - где Celery-задачи и конфиг Celery/beat,
   - где сигналы (если используются),
   - как Plane хранит файлы (S3/MinIO),
   - точки интеграции для `ai`: куда вешать сигналы ингеста, куда добавлять URL ИИ-эндпоинтов.
2. Описать локальный dev-цикл: как поднять backend локально, как прогнать миграции и тесты, как подключить наш `ai` в dev.
3. Провести 30-минутный синк с командой по этому документу.

## 📦 Артефакты

- `ONBOARDING.md`: карта кодовой базы + точки интеграции `ai` + dev-цикл
- Проведённый синк (отметка в задаче)

## ⚠️ Важно

Привязывай всё к реальным путям из репо `apps/api` и к SCHEMA.md (0.2), а не к общим словам про Django. Цель — чтобы человек открыл документ и сразу понял, куда писать код, а не «где-то в Django».
