## 🎯 Цель

Определить, под каким сервером работает `api`-контейнер Plane — **ASGI** (uvicorn/daphne) или **WSGI** (gunicorn). От этого зависит, какую из двух взаимоисключающих реализаций SSE-стриминга использовать в задаче 2.3.

## 📋 Контекст для Claude Code

SSE-стриминг ответа Claude рисует текст по мере генерации. Реализация принципиально разная:
- **WSGI** → синхронный генератор, отдающий строки (проще, но блокирует воркер на время стрима).
- **ASGI** → async-генератор + `AsyncAnthropic` + `sync_to_async` для любых ORM-вызовов (правильно, но сложнее; иначе `SynchronousOnlyOperation`).

Ошибка с выбором = либо краш под нагрузкой, либо блокировка воркеров.

## ✅ Что сделать

1. Определить тип сервера:
   ```bash
   docker compose exec api ps aux | grep -E "gunicorn|uvicorn|daphne"
   docker compose exec api cat ./bin/docker-entrypoint-api.sh   # посмотреть команду запуска
   ```
2. Интерпретировать:
   - `gunicorn` без uvicorn-воркеров → **WSGI**
   - `uvicorn` / `daphne` / `gunicorn -k uvicorn.workers.UvicornWorker` → **ASGI**
3. Зафиксировать вывод в `STREAMING.md`: какой режим, какой вариант SSE использовать в 2.3, и почему.
4. Если ASGI — отметить требование `CONN_MAX_AGE=0` для async-безопасности соединений БД (или отдельный DB-алиас под ИИ-вьюхи).
