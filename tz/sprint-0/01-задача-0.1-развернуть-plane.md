## 🎯 Цель

Развернуть чистый self-hosted **Plane Community Edition** на проде (4 vCPU / 8 ГБ / 40 ГБ, Ubuntu 24.04), убедиться что стек поднимается и **не уходит в OOM-перезапуск**. Это базовый слой, поверх которого встанет вся ИИ-надстройка.

## 📋 Контекст для Claude Code

Plane — тяжёлое микросервисное приложение (~13 контейнеров: api, worker, beat-worker, web, space, admin, postgres, redis, rabbitmq, minio, proxy). Минимум 4 ГБ RAM, рекомендовано 8 ГБ. На 4 ГБ контейнеры циклически рестартуют с OOM. Backend живёт в `apps/api` (Django). Установка идёт через официальный `setup.sh`.

## ✅ Что сделать

1. Подготовить сервер: Docker + Docker Compose (последняя версия), проверить `free -h ≥ 8Gi`, `nproc ≥ 4`, `df -h / ≥ 40Gb`.
2. Скачать и запустить установщик Plane CE:
   ```bash
   mkdir plane-selfhost && cd plane-selfhost
   curl -fsSL -o setup.sh https://github.com/makeplane/plane/releases/latest/download/setup.sh
   chmod +x setup.sh
   ./setup.sh   # выбрать Install (Community), затем Start
   ```
3. Дождаться миграций (контейнер `migrator` отрабатывает и выходит).
4. Проверить, что **все** контейнеры в состоянии `running`/`healthy`, ни один не в `Restarting`.
5. Открыть веб-интерфейс, создать первого админа и тестовый воркспейс.
6. Зафиксировать в README: версию Plane, имена контейнеров, имя docker-сети, путь рабочей директории внутри `api`-контейнера.

## 🔍 Команды проверки

```bash
free -h                      # MemTotal >= 8Gi
docker compose ps            # все running/healthy, НЕТ Restarting
docker compose logs api | tail -50   # нет фатальных ошибок
docker compose exec api pwd          # зафиксировать рабочую директорию
docker network ls | grep plane       # имя сети
```

## 📦 Артефакты

## ⚠️ Риски / на что смотреть

- Если контейнеры рестартуют → почти наверняка RAM. Проверь `dmesg | grep -i oom`. На 8 ГБ не должно быть.
- Внешние БД/хранилище для прода рекомендованы, но для прототипа допустим встроенный MinIO + локальный Postgres.
- Не настраивай ИИ на этом шаге — только чистый Plane.
