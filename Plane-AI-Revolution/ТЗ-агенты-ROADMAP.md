# Roadmap агентских фаз — индекс ТЗ

> 16 ТЗ + контекст для Claude Code. Расширение базовых 7 спринтов до автономной multi-agent системы.

## Все задачи по фазам

### Фаза 7 — PLANNER (декомпозиция цели)
- **7.1** — Модели агентской системы (ProjectGoal, AgentAction, PredictedRisk, TeamVelocity)
- **7.2** — Decision Layer (когда агент сам, когда спрашивает) ⭐ безопасность
- **7.3** — PLANNER: декомпозиция + валидация против галлюцинаций
- **7.4** — Создание задач в Plane + защита от петли
- **7.5** — UI целей и превью плана (стиль Plane)

### Фаза 8 — MONITOR (мониторинг + предсказание)
- **8.1** — Event Stream (события Plane → агенты)
- **8.2** — Сбор velocity + ML-модель (LightGBM, холодный старт)
- **8.3** — MONITOR: детекция рисков + UI (только наблюдение)

### Фаза 9 — EXECUTOR + ESCALATOR
- **9.1** — EXECUTOR: назначение и перераспределение
- **9.2** — ESCALATOR: эскалация критичного с вариантами

### Фаза 10 — ANALYST + COMMUNICATOR
- **10.1** — ANALYST: анализ velocity и узких мест
- **10.2** — COMMUNICATOR: автоматические отчёты

### Фаза 11 — ORCHESTRATOR (координация)
- **11.1** — ORCHESTRATOR: координация на LangGraph
- **11.2** — Защита от runaway: circuit breaker + kill-switch ⭐ безопасность

### Фаза 12 — Визуальная интеграция
- **12.1** — Единый UI агентов в стиле Plane + лента активности
- **12.2** — Тесты безопасности + поэтапная приёмка

## Порядок включения агентов (критично)

Не все сразу. По одному, каждый за флагом, с gate:

1. PLANNER (режим CONFIRM — предлагает) → приёмка
2. MONITOR (только наблюдение) → приёмка
3. EXECUTOR (NOTIFY → AUTO для мелочи) → приёмка
4. ESCALATOR → приёмка
5. ANALYST → приёмка
6. COMMUNICATOR → приёмка
7. ORCHESTRATOR (координация) → финальная приёмка

## Сквозные предохранители (в каждом ТЗ)

- **Decision Layer** (7.2): обратимое сам, необратимое → человек, удаление → никогда
- **Защита от петли** (7.4, 8.1): `_modified_by_agent`
- **Circuit breaker + kill-switch** (11.2): автостоп + ручная остановка
- **Валидация выхода** (7.3): PLANNER может галлюцинировать
- **Полный аудит** (везде): AgentAction с обоснованием
- **ACL** (везде): агенты в границах прав

## Реалистичные оговорки

- **Токены:** multi-agent дорогой, нужны Haiku + дебаунс + кэш, мониторить с дня 1
- **Сервер:** для агентов 16 ГБ (NLs-4), 8 ГБ не хватит
- **Холодный старт:** первые недели эвристики, не ML
- **Срок:** ~9 недель поверх базовых 7 спринтов

## Связь с базовой версией

Надстройка, не замена. Использует RAG (спринт 2), agent loop (4), простых агентов (5), токены (1), ACL (0.6), kill-switch (6.5). Сначала базовая версия работает, потом агенты поверх.
