# PLANE AI REVOLUTION — Автономная система управления проектами

> **Не надстройка, а революция:** от «умного помощника» к **системе агентов, которые самостоятельно двигают проект к результату**.

## 🔥 Сдвиг парадигмы

### БЫЛО (все ИИ-трекеры, включая Asana AI)
**Человек управляет → ИИ помогает**

- Человек создаёт задачи → ИИ предлагает описание
- Человек ищет информацию → ИИ отвечает на вопросы
- Человек планирует → ИИ генерирует план как текст
- Человек следит за прогрессом → ИИ показывает дашборды
- **ИИ реактивен** — отвечает на команды, ждёт указаний

### СТАЛО (наша система)
**Пользователь задаёт цель → система самостоятельно достигает**

- Пользователь: *«Запустить мобильное приложение к 1 июня»*
- Система:
  - Декомпозирует цель в 60 задач с зависимостями
  - Назначает на команду с учётом загрузки
  - Следит за прогрессом в реальном времени
  - **Сама видит** блокеры и риски
  - **Сама перераспределяет** работу при задержках
  - **Сама эскалирует** критичное PM
  - **Сама пишет** отчёты стейкхолдерам
- **ИИ проактивен** — видит проблемы раньше людей и решает их

## 👥 7 агентов детально

### 1. 🧠 ORCHESTRATOR (Оркестратор)
**Роль:** Главный мозг системы, координатор всех агентов

**Что делает:**
- Получает цель и **понимает её** через RAG (анализирует похожие проекты)
- Разбивает цель на стратегические фазы
- Координирует других агентов
- Принимает стратегические решения (MVP vs full scope)
- Управляет конфликтами между агентами

**Пример:**
```
Вход: «Запустить приложение к 1 июня, бюджет $50k, команда 4 человека»

ORCHESTRATOR анализирует:
→ RAG находит: похожий проект занял 8 недель (56 дней)
→ У нас: 45 дней
→ Решение: «Агрессивный MVP, фокус на критичных фичах»
→ PLANNER: «Составь план на 45 дней, только core»
→ ANALYST: «Найди, что тормозит на iOS-проектах»
```

---

### 2. 📋 PLANNER (Планировщик)
**Роль:** Превращает цель в дерево задач

**Что делает:**
- Декомпозирует цель в иерархию (эпики → задачи → подзадачи)
- Оценивает сроки на основе **истории команды**
- Выстраивает зависимости, определяет критический путь
- Создаёт всё **реально в Plane** (не текст, а задачи)

**Пример:**
```
PLANNER создаёт в Plane:
┌─ Epic: iOS App Launch (1 июня)
│  ├─ Phase 1: Design (5 дней)
│  ├─ Phase 2: Core Features (20 дней) ← критический путь
│  ├─ Phase 3: Testing (10 дней)
│  └─ Phase 4: App Store (10 дней)

✓ 60 задач созданы
✓ Зависимости проставлены (45 связей)
✓ Оценки на основе velocity команды (из RAG)
```

---

### 3. ⚡ EXECUTOR (Исполнитель)
**Роль:** Двигает работу — назначает, приоритизирует, разблокирует

**Что делает:**
- Назначает задачи (учитывает загрузку, навыки, историю)
- Приоритизирует
- Создаёт подзадачи
- **Перераспределяет** при блокерах
- Следит, чтобы критический путь не стопорился

**Пример:**
```
День 1: смотрит загрузку команды → назначает первые 12 задач
День 5: MONITOR сообщил о задержке →
  ✓ Некритичное откладывает
  ✓ Часть работы передаёт фрилансеру
  ✓ Зависимые задачи перепланирует
```

---

### 4. 👁️ MONITOR (Наблюдатель)
**Роль:** Непрерывно следит, детектирует риски

**Что делает:**
- Мониторит прогресс в реальном времени
- Детектирует задержки и блокеры
- **Предсказывает** срыв дедлайнов (ML)
- Видит перегрузку команды

**Пример:**
```
День 3: TASK-001 — прогресс 20% за 2 дня (ожидалось 66%)
ML-предсказание: задержка 85%, +2 дня, влияние КРИТИЧЕСКОЕ
→ MONITOR передаёт ESCALATOR
```

---

### 5. 🚨 ESCALATOR (Эскалятор)
**Роль:** Определяет критичное, вовлекает людей

**Что делает:**
- Получает риски от MONITOR
- Определяет: критично или терпимо
- Выбирает, кого алертить
- Формирует **варианты решения** с расчётом
- Создаёт задачи-алерты

**Пример:**
```
🚨 РИСК СРЫВА ДЕДЛАЙНА
Задача: Design (TASK-001), блокирует 8 задач

Варианты:
1. Фрилансер ($2k, +0 дней)
2. Упростить (−2 дня, риск wow-эффекта)
3. Сдвинуть дедлайн (переговоры)

⭐ Рекомендация: Вариант 2 (MVP)
[Применить 1] [Применить 2] [Применить 3]
```


---

### 6. 🔍 ANALYST (Аналитик)
**Роль:** Анализирует процессы, находит узкие места

**Что делает:**
- Анализирует velocity команды
- Находит паттерны (что тормозит, где застревают)
- Детектирует узкие места
- Предлагает улучшения процесса
- Учится на истории

**Пример:**
```
📊 НАЙДЕНО УЗКОЕ МЕСТО
Код-ревью занимает 2 дня в среднем
Причина: Вова — единственный ревьюер iOS
Влияние: −15% velocity команды

💡 Решение: внешний ревьюер ($1.5k) или обучить QA
Эффект: +15% velocity, экономия ~7 дней
[Нанять] [Обучить QA] [Игнорировать]
```

---

### 7. 🤝 COMMUNICATOR (Коммуникатор)
**Роль:** Берёт на себя всю коммуникацию

**Что делает:**
- Собирает статус-отчёты автоматически
- Генерит апдейты стейкхолдерам (каждую пятницу)
- Готовит материалы для митингов
- Пишет release notes
- Отвечает на типовые вопросы

**Пример (автоотчёт, пятница 18:00):**
```
📧 Еженедельный отчёт: iOS App Launch
ПРОГРЕСС: 45% (на треке 🟢)

Завершено: Design, Setup, Авторизация
В работе (70%): Главный экран, Профиль, Push
Не начато: QA, App Store

РИСКИ: 1 средний
⚠️ Интеграция с backend может задержаться на 2 дня
   Mitigation: работаем с моками

ДЕДЛАЙН 1 июня: ДОСТИЖИМ ✅ (уверенность 75%)
```

## 🎬 Полный сценарий (45 дней проекта)

**Пользователь:** «Запустить iOS-приложение к 1 июня, команда 4 человека, бюджет $50k, MVP-подход»

**День 1, 10:00 — ORCHESTRATOR** анализирует через RAG, видит похожий проект (56 дней vs наши 45), решает: агрессивный MVP.

**День 1, 10:15 — PLANNER** создаёт 60 задач, 5 фаз, 45 зависимостей, оценки из velocity команды.

**День 1, 10:30 — EXECUTOR** смотрит загрузку, назначает первые 12 задач оптимально.

**День 3, 14:00 — MONITOR** видит: дизайн 20% за 2 дня, предсказывает задержку +4 дня, блокирует 8 задач.

**День 3, 14:05 — ESCALATOR** создаёт алерт PM с 3 вариантами и рекомендацией.

**День 3, 14:10 — PM** выбирает «упростить дизайн».

**День 3, 14:15 — EXECUTOR** корректирует scope, пересчитывает план — дедлайн снова достижим.

**День 10 — ANALYST** находит узкое место в код-ревью, предлагает решение (+7 дней экономии).

**День 20 — COMMUNICATOR** шлёт автоотчёт стейкхолдерам.

**День 45 — Запуск в срок.** PM потратил 3ч/неделю вместо 15 (−70%).

Что система сделала автономно: 60 задач, оптимальные назначения, 12 предсказанных рисков, 3 эскалации, 8 перераспределений, 2 найденных узких места, 6 отчётов.

## 🛠️ Технологическая база (поверх базовой версии)

**Базовая версия уже даёт:** RAG (pgvector + Claude), генерацию, bulk-операции, простые агенты.

**Добавляем для революции:**
1. **Agent Framework** — LangGraph/AutoGen для координации multi-agent, event-driven
2. **Planning Engine** — декомпозиция целей, дерево зависимостей, критический путь
3. **Prediction Model** — ML (LightGBM) на истории: предсказание задержек
4. **Memory System** — долгосрочная память агентов (векторы + граф знаний)
5. **Event Stream** — real-time мониторинг Plane (webhooks + RabbitMQ)
6. **Decision Layer** — правила: когда агент сам, когда эскалирует (обратимое vs необратимое)

### Новые модели данных
```python
class ProjectGoal(models.Model):
    description = TextField()    # «Запустить к 1 июня»
    deadline = DateField()
    constraints = JSONField()     # бюджет, команда
    status = CharField()          # planning/executing/at_risk/done

class AgentAction(models.Model):
    agent_type = CharField()      # PLANNER/EXECUTOR/...
    action_type = CharField()
    target = ForeignKey(Issue)
    reasoning = TextField()       # почему так решил
    approved_by_user = BooleanField()

class PredictedRisk(models.Model):
    task = ForeignKey(Issue)
    risk_type = CharField()       # delay/blocker/overload
    confidence = FloatField()     # 0.85
    impact = CharField()          # critical/high/medium/low
    suggested_actions = JSONField()

class TeamVelocity(models.Model):
    user = ForeignKey(User)
    task_type = CharField()
    estimated_hours = IntegerField()
    actual_hours = IntegerField()
```
