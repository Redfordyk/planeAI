# GDPR — трансферы данных в OpenAI / Anthropic (ТЗ 0.7)

> ⚠️ **Этот документ — каркас, который заполняет Илья (PM) после оформления DPA**. Технический скелет сделан Claude Code, но юридические шаги (подпись DPA, выбор правового основания, проектные ключи с лимитами) — за человеком. Поля помечены как `[заполнить]` / `[ ]`.

## TL;DR

Контент задач Plane (`Issue.name`, `Issue.description_*`, `IssueComment.comment_*`, `Page.description_*`) уходит в два external processor'а:

- **OpenAI** — для эмбеддингов (`text-embedding-3-small`, 1536 dim).
- **Anthropic** — для генерации (`claude-sonnet-4-6`, `claude-haiku-4-5-20251001`).

Команда находится в **EU (Франкфурт)**, оба провайдера — США / UK. По GDPR это international data transfer, требующий: DPA, SCC (стандартные контрактные оговорки), и желательно zero-retention.

## Реестр трансферов

| Что отправляется | Куда | Зачем | Какая модель Plane (см. [SCHEMA.md](SCHEMA.md)) | Регулярность |
|---|---|---|---|---|
| `name` + `description_stripped` задачи | OpenAI | вычисление эмбеддинга для RAG | `db.Issue` | при создании / обновлении |
| `comment_stripped` коммента | OpenAI | то же | `db.IssueComment` | при создании / обновлении |
| `name` + `description_stripped` страницы | OpenAI | то же | `db.Page` | при создании / обновлении |
| Запрос пользователя + top-k чанков | Anthropic | генерация ответа RAG | (не модель Plane — формируется на лету) | по запросу пользователя |
| Текст задачи + промпт | Anthropic | авто-саммари, триаж, bulk-классификация | `db.Issue` | пакетно (Celery) |

Чего **НЕ** отправляем:

- Пароли, токены, любые секреты — не индексируются и не передаются.
- Содержимое аттачментов (`db.FileAsset`) — пока вне scope.
- Личные данные пользователей сверх того, что попало в текст задачи (email/имя автора задачи могут оказаться в теле — это известный риск; на проде закроем редактированием через ТЗ из спринта 6 по приватности).
- Проекты, для которых выставлен флаг `AIProjectSettings.exclude_from_ai=True` (см. ниже).

## Правовое основание

`[заполнить — выбрать одно после согласования с юристом]`

- [ ] Art. 6(1)(b) GDPR — necessary for performance of contract with users (если хост Plane — наш SaaS-продукт).
- [ ] Art. 6(1)(f) GDPR — legitimate interest, с DPIA (если on-prem у клиента, мы processor).
- [ ] Art. 6(1)(a) GDPR — explicit consent (если включаем opt-in для AI-фич в воркспейсе).

Текущее предположение команды: **Art. 6(1)(f)** + opt-in на уровне воркспейса (`WorkspaceAIConfig.enabled`). Подтвердить с юристом до прода (блокер 6.7).
