### 4. Расход токенов

После прогона 10 вопросов выполнить на staging:

```bash
docker compose -p plane-staging exec api python manage.py shell -c "
from datetime import timedelta
from django.utils import timezone
from ai.models import AIUsageLog
since = timezone.now() - timedelta(hours=1)
qs = AIUsageLog.objects.filter(created_at__gte=since)
print('rows:', qs.count())
for r in qs.values('feature','model').annotate(
    n=__import__('django.db.models').db.models.Count('id'),
    i=__import__('django.db.models').db.models.Sum('input_tokens'),
    o=__import__('django.db.models').db.models.Sum('output_tokens'),
    cost=__import__('django.db.models').db.models.Sum('cost_usd')):
    print(r)
"
```

- [ ] Средняя стоимость одного вопроса (`cost_usd / n` для feature='intent_search') — приемлема. Ориентир: **< $0.05 за ответ** на текущих ценах (claude-sonnet-4-6 + text-embedding-3-small).
- [ ] Расход на embed по 10 вопросам — должен совпадать с ~10 × 1 эмбединг запроса (~50–200 токенов суммарно).
- [ ] Никаких `feature='intent_search'` без последующего `cost_usd > 0` (значит, record_usage не оторвался).

## ⚠️ Подсказки из ТЗ

Если качество ответов низкое — **проблема почти всегда в retrieval**, а не в Claude. Проверять в порядке:

1. `index-status.coverage` ≥ 95% (все ли источники проиндексированы).
2. Распределение чанков по источникам: `SELECT source_type, COUNT(*) FROM ai_document_chunk GROUP BY 1;`.
3. Ручной retrieve в shell: `from ai.search import retrieve; retrieve(workspace_id=..., user=..., query='...')` — посмотреть, какие чанки реально приходят top-K.
4. Только если retrieve выдаёт релевантные чанки, а ответ всё равно плохой — править промпт.
