# RELEASE — постепенный rollout planeAI (ТЗ 6.8)

> Финальный runbook релиза. Не «врубить всем сразу», а трёхфазный rollout: сам PM → cohort → вся команда. Если что-то идёт не так — откат через kill switch ([ROLLBACK.md](ROLLBACK.md)) затрагивает минимум людей.
>
> **Кто читает:** Илья (PM, ведёт), Никита (QA, on-call), Костя/Вова (FullStack, дежурят). **Когда:** в день релиза + 3-5 дней наблюдения после.

---

## Pre-flight (ещё раз, последний)

Перед тем как начать — все три гейта должны быть зелёными в один и тот же день:

```bash
# 1. Acceptance (TZ 6.6) — DPA, бэкап, AI config, health
docker compose -p plane-ce exec api python manage.py acceptance_check \
  --workspace <prod-workspace-id>

# 2. GDPR (TZ 6.7) — privacy, encryption, feature tagging
docker compose -p plane-ce exec api python manage.py gdpr_check \
  --workspace <prod-workspace-id>

# 3. Подписан GDPR-RELEASE.md (TZ 6.7) — все 8 пунктов с подписями
git log -1 --format="%H %s" GDPR-RELEASE.md
```

Любой `NOT GO` = откладывать релиз. **Не подгонять под календарь.**

## Фаза 1 — Только сам PM (день 0, утро)

> Цель: убедиться, что в боевом окружении ничего не выглядит сломанным, прежде чем кто-то другой увидит. Длительность: 1-2 часа.

### Включение

```bash
# Включить ИИ только в одном тестовом воркспейсе — твоём личном.
docker compose -p plane-ce exec api python manage.py enable_ai \
  --workspace <pm-personal-workspace>
```

### Smoke (60-90 минут)

- [ ] Открыть `<workspace>/settings/ai-usage` — дашборд расхода работает, показывает 0 за сегодня.
- [ ] Открыть `<workspace>/settings/ai-agent` — toggle Off (агент ещё не нужен в фазе 1).
- [ ] Сделать **5 поисковых запросов** разной сложности:
  - простой: «что у меня открыто на этой неделе?»
  - конкретный: «задачи Васи по платежам»
  - сложный: «есть ли в проекте X задачи, которые могут блокировать релиз?»
  - с пустым результатом: что-то заведомо отсутствующее
  - с длинным ответом: «расскажи про архитектуру X»
- [ ] Для каждого: время до первого `delta` ≤ 3 сек, sources содержат реальные ссылки, ответ осмысленный, нет фактологических галлюцинаций.
- [ ] Открыть `/api/ai/health/` — `status: ok`.
- [ ] Открыть Grafana dashboard — расход появляется, нет красных линий.
- [ ] Проверить дашборд: `cost_usd_24h > 0`, `feature=intent_search` растёт, остальные = 0.

### Решение

- ✅ **OK** → продолжать на фазу 2.
- ❌ **Что-то не так** → выключить (`disable_ai --workspace <pm-personal>`), записать симптом в `RELEASE-LOG.md` (создать сейчас), эскалация Косте/Вове.

## Фаза 2 — Cohort (день 0, после обеда)

> Цель: 3-5 человек, которые **согласились быть early adopters**. Включить, дать пользоваться 2-3 дня, активно слушать фидбэк.

### Кого включать первыми

| Кого | Почему |
|---|---|
| Сам PM (Илья) | уже включён в фазе 1 |
| 1-2 FullStack (Костя/Вова) | смогут сами отдиагностировать симптом |
| 1 QA (Никита) | будет специально пробовать сломать |
| 1-2 «обычных» пользователя из команды | объективная оценка качества |

**Не больше 5.** В этой фазе цель — не нагрузка, а наблюдение.

### Включение

```bash
# Не глобальный --all-workspaces, а по одному воркспейсу. Если у
# каждого участника свой workspace — список UUID-ов, по одному
# вызову. Если воркспейс один общий — один enable_ai.
docker compose -p plane-ce exec api python manage.py enable_ai \
  --workspace <cohort-workspace-id>
```

Если есть `<workspace>/settings/ai-agent` toggle — оставить Off (фаза 2 — только поиск, агент включается в фазе 3 после стабилизации).

### Уведомление cohort

Отправить через Slack DM (НЕ публичный канал — публичное объявление в фазе 3):

```
@cohort — ИИ-фичи доступны в твоём воркспейсе с сегодня.

Что попробовать:
- /<slug>/settings/ai-search — спроси что-то по своим задачам
- /<slug>/settings/ai-usage — посмотреть, сколько я уже потратил

Что НЕ доступно ещё:
- ИИ-агент (включим в фазе 3 после твоих отзывов)
- Bulk-операции (TBD)

Фидбэк (важно!):
- что понравилось / что бесит
- качество ответов поиска: точные / галлюцинации
- скорость
- любая странность

Куда писать: Slack #planeai-feedback или прямо мне.

Срок наблюдения — 2-3 дня. Потом включаем всем.

Спасибо, Илья
```

### Активный мониторинг (день 0, вечер; день 1; день 2)

Каждое утро PM запускает:

```bash
docker compose -p plane-ce exec api python manage.py rollout_status \
  --since 24
```

Читает разделы для каждого cohort-воркспейса. Ожидаемое:

| Метрика | OK | Подозрительно | Тревожно |
|---|---|---|---|
| `calls_24h` | 5-30 (зависит от использования) | 0 (никто не пользуется) или >300 | >1000 (петля?) |
| `budget ratio` | <0.10 | 0.10-0.30 | >0.30 в первые дни |
| `cost_usd_24h` | $0.01-1.00 | $1-5 | >$5/день/чел |
| `agent_actions` | n/a (агент off) | — | — |
| `notes` | пусто | 1-2 ноты | budget warning / silent ws |

Если в `notes` есть `budget warning` — расследовать сегодня же. Если `silent workspace` — спросить cohort, чему не пользуется (не работает или просто не нужно).

### Сбор фидбэка

Канал `#planeai-feedback` (или дедикат для cohort). Каждый день в 18:00 — короткий saтet from PM в этом канале:

```
Дневной саммари (день N rollout-а):
- запросов было N, стоимость $X
- что собрал из фидбэка (3-5 буллетов)
- что меня тревожит (если есть)
- что планирую на завтра
```

PM ведёт `feedback-log.md` — заметки по каждому отзыву, чтобы потом разнести их в [PHASE-2-BACKLOG.md](PHASE-2-BACKLOG.md).

### Решение по итогам фазы 2 (день 2 или 3)

После 2-3 дней:

- ✅ **GO на фазу 3** — все три критерия:
  - инцидентов нет (или были отработаны)
  - расход в рамках ожиданий (`cost_usd_24h × team_size ≤ budget/30`)
  - cohort фидбэк позитивный или нейтральный (`>= 60% позитива`)
- ❌ **STOP** — что-то из критериев не выполнено:
  - снять включение с cohort (`disable_ai`),
  - провести разбор причин,
  - доработать,
  - повторить фазу 2.

## Фаза 3 — Вся команда (день 2-3)

> Цель: открыть ИИ-фичи всей команде. Расход скачёт, наблюдение интенсивнее первые 48 часов.

### Подготовка

- [ ] Разослать команде уведомление по шаблону [`docs/team-notice-ai-processing.md`](docs/team-notice-ai-processing.md) (фактически разослать, не «в плане»).
- [ ] Запостить `User Guide` — копия [`docs/user-guide.md`](docs/user-guide.md) — в Slack `#general` с pinned-сообщением.
- [ ] Открыть `#planeai-feedback` для всех, не только cohort.
- [ ] Убедиться, что Никита (QA) и Костя/Вова (FullStack) дежурят следующие 48 часов в Slack.

### Включение

Глобально — все воркспейсы продакшен-инсталляции:

```bash
# Глобальный enable. --confirm обязателен (защита от случайной
# выкатки на чужие воркспейсы).
docker compose -p plane-ce exec api python manage.py enable_ai \
  --all-workspaces --confirm
```

ИЛИ воркспейс-за-воркспейсом, если нужна тонкая настройка:

```bash
for ws in <list-of-workspace-ids>; do
  docker compose -p plane-ce exec api python manage.py enable_ai \
    --workspace "$ws"
done
```

### Включение агента — отдельно и осторожно

Агент **не** включается одновременно с поиском. После 24 часов стабильной фазы 3:

- [ ] Включить агента в **одном** воркспейсе и **на одном** проекте через `<workspace>/settings/ai-agent`.
- [ ] Через 4-6 часов: `rollout_status --workspace <ws>` — `applied/rejected` соотношение разумное (rejected не > applied).
- [ ] Через 24 часа: расширить на остальные воркспейсы.

Алерт `PlaneAIAgentLoop` (TZ 6.2) должен сработать в случае реальной петли — но PM **активно проверяет** агента в первые 48 часов.

### Активный мониторинг (3-5 дней)

Каждое утро PM:

```bash
# 1. Snapshot всех воркспейсов
docker compose -p plane-ce exec api python manage.py rollout_status \
  --json | jq '.workspaces | map(select(.notes | length > 0))'
# → пусто = всё ок; список = разобрать заметки

# 2. Проверка health
curl -fsS http://<host>/api/ai/health/ | jq .

# 3. Проверка Alertmanager
curl -fsS http://<host>:9093/api/v2/alerts | jq '. | length'
# → 0 = идеально
```

Если что-то выходит за норму:

| Симптом | Действие |
|---|---|
| Recurring `agent loop` alert на одном ws | toggle Off для этого ws через UI |
| Budget critical для воркспейса | расследовать через дашборд расхода → BUDGET.md |
| Provider errors > 10/мин | проверить status pages, если их инцидент — wait, если наш — escalate |
| Silent workspaces (`calls_24h=0`) > 2 дня | UX-проблема: люди не находят фичу, а не баг. Уточнить с командой. |
| Жалобы на качество поиска | собрать конкретные примеры в `feedback-log.md` — это материал для phase 2 backlog |

### Ежедневный саммари — продолжение

PM продолжает делать дневной саммари в Slack как в фазе 2, до конца недели наблюдения (день 7 после фазы 3).

## Сбор фидбэка — формализация

После 7 дней rollout — выслать команде **короткий опросник** (Google Forms или внутренний). Шаблон вопросов:

1. **Какими фичами пользуешься?** (multi-select: поиск / саммари / bulk / агент / дашборд)
2. **Как часто?** (ежедневно / несколько раз в неделю / реже / не использую)
3. **Качество поиска: 1-5.** Что хорошо? Что плохо?
4. **Если использовал агента — нашёл его действия полезными? Назойливыми?**
5. **Сколько раз ты делал «отменить» действие агента?**
6. **Стоит ли это денег, которые мы за это платим?** (вопрос ценности)
7. **3 фичи, которые ты бы добавил.**
8. **3 вещи, которые ты бы убрал/исправил.**

Дедлайн опроса — день +10 от старта фазы 3. Результаты переносятся в [PHASE-2-BACKLOG.md](PHASE-2-BACKLOG.md).

## Экстренный откат

В любой момент фаз 1-3 при «горит»:

```bash
# Глобальный kill switch — все воркспейсы.
docker compose -p plane-ce exec api python manage.py disable_ai \
  --all-workspaces --confirm

# Plane живёт, ИИ-эндпоинты возвращают 403.
# Подробнее: ROLLBACK.md → L1 kill switch.
```

После kill switch — обязательно:
1. Запостить в `#planeai-feedback`: «ИИ временно выключен, разбираемся».
2. Запостить в `#general`: «ИИ-фичи временно недоступны, Plane работает как обычно».
3. Создать post-mortem задачу в Plane, тэг `planeai/incident`.
4. Описать в `RELEASE-LOG.md` (создаётся в фазе 1): что случилось, когда, как лечили, что дальше.

Включать обратно — только после фикса и переподтверждения acceptance/gdpr-чеков.
